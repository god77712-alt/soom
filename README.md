## 개요

크리에이터가 **다음 촬영지를 고를 때 보는 도구**다. 채널을 넣으면 그 채널이 잘 찍는 소재를
판별하고, **같은 소재를 찍을 수 있는 인구감소지역 촬영지**를 성과 데이터와 함께 펼친다.

한국관광공사 TourAPI **5만 곳**과 유튜브 성과 **8.3만 편**을 **소재(subject)라는 하나의 축**으로
붙인 것이 이 서비스의 실체다.

## 과제 — 일회성 관광의 한계

인구감소지역 89곳의 관광 사업은 대부분 **축제·행사 중심**이다. 예산을 써서 사람을 한 번 모으고,
행사가 끝나면 방문 동기도 같이 사라진다. **남는 것이 없다.**

- 홍보물은 게시 기간이 끝나면 사라진다 — **검색되지 않는다**
- 공공데이터 6.4만 곳은 **소재로 검색할 수 없다.** 분류는 있어도 성과가 없다
- 그래서 크리에이터의 촬영지 후보에 **애초에 오르지 못한다**

## 해결 — 크리에이터를 경유해 지속 유입으로 바꾼다

촬영은 일회성이지만 **영상은 남는다.** 검색되고, 추천되고, 몇 년 뒤에도 사람을 데려온다.
그래서 방문객이 아니라 **크리에이터**를 움직인다.

| | |
|---|---|
| **① 후보지에 올린다** | 인구감소지역을 “처음 듣는 지명”이 아니라 **같은 소재를 찍을 수 있는 선택지**로 보여준다. 희소성 가중치가 없으면 서울·부산만 남는다 |
| **② 예상 성과를 보여준다** | 그 소재가 이 채널 규모에서 낸 성과를 배수와 **예상 도달 범위**로. 단일 숫자로 쓰지 않는다 |
| **③ 의심을 걷어낸다** | “별로라서 아무도 안 간 것 아닌가”에 답하지 못하면 움직이지 않는다. 상세 화면이 6단으로 이 순서를 밟는다 |

계산의 뼈대:

- 성과 = **조회수 ÷ 구독자(vsr)** — 채널 크기를 지워야 작은 채널의 대박이 보인다
- 숨 스코어 = 소재 점수 × 희소성 `1 / log(1 + 영상수)`
- 화면은 **“오일장 3.2× (정선·화개장터 기준)”** 처럼 **출처를 밝힌 소재 성적**만 말한다

## 기능 명세

| 화면 | 사용자가 하는 일 | 서비스가 주는 것 | 데이터 근거 |
|---|---|---|---|
| **채널 분석** `/` | 채널 URL 을 넣는다 (없으면 소재를 직접 고른다) | 롱폼·쇼츠 성과, **잘 되는 소재 태그 3~5개**. 평균이 아니라 **상위 성과 영상**에서 뽑는다 | YouTube Data API · LLM 소재 분류 |
| **촬영지 추천** `/` | 추천 5곳을 훑고 카드를 펼친다 | 장소 · **소재 성적과 그 출처** · **경쟁 영상 수** · 잘 된 영상의 구성 · 묶어 찍을 곳 | 숨 스코어 |
| **소재로 찾기** `/subject` | 소재를 고르고 시도로 좁힌다 | 그 소재를 찍을 수 있는 곳 **전부** · 장날 달력 · 일출입 시각. 예측이 아니라 **목록**이다 | TourAPI + 전통시장·폐교·철도역 표준데이터 |
| **장소 상세** `/place` | 가도 되는지 판단한다 | **6단 근거** — ① 소재가 먹힌다 ② 여긴 비어 있다 ③ **별로라서가 아니다** ④ 당신이면 이 정도 ⑤ 이렇게 찍는다 ⑥ 이렇게 머문다 | 유튜브 임베드 · 천문연 출몰시각 · 관광사진 |
| **기관용** `/admin` | 지역별 현황을 본다 | 시군구별 소재 보유 현황 **(모수 병기)** · 팸투어 채널 매칭. **못 재는 KPI 는 그리지 않는다** | 지역코드 100% 복원 집계 |

## 근거 — 서비스가 선 가정을 실제로 검정했다

| | 결과 |
|---|---|
| A · 소재가 성과를 가르는가 | ✅ 그렇다 (p=0.0007, 구독자 구성 보정 후) |
| B · 비어 있는 곳이 유리한가 | ❌ **뒷받침되지 않는다** (곡성 0.79배) |
| 분산 분해 | 성과의 **74.2%는 채널 본인** — 소재가 다툴 수 있는 몫은 25.8% |

가설 A 도 **BH 보정 후 유의한 쌍은 0개**다. → 점수는 **순위로만** 쓰고 근소한 차이를
의미 있는 것처럼 그리지 않는다. 가설 B 가 기각됐으므로 희소성 가중치는
**예측이 아니라 정책**이다 — 화면은 `경쟁 영상 0편` 이라는 **사실만** 말한다.

`npm run eval:hypothesis` 로 언제든 다시 잰다.

## 구조

```
수집 → 정리 → 태깅 → 점수 → 화면
```

**화면은 어떤 외부 API 도 부르지 않는다.** 빌드 시점에 구운 JSON(`src/data/real/*`)만 읽는다.
방문자가 늘어도 쿼터 소비는 0이고, 시연 중에 서비스가 멈추지 않는다.

| 문서 | 역할 |
|---|---|
| [`CLAUDE.md`](CLAUDE.md) | **작업 규칙과 실측 기록.** 손대기 전에 반드시 읽는다 |
| [`SPEC.md`](SPEC.md) | 전체 설계 (데이터 모델·계산식·화면) |
| `scripts/` | 수집·가공·검증·내보내기 |
| `src/` | Next.js 화면 |

## 돌려보기

```bash
npm install
cp .env.example .env      # 키를 채운다. 화면만 볼 거면 비워도 된다
npm run dev
```

**데이터는 저장소에 없다.** `data/*.db` 와 `.env` 는 커밋하지 않는다 —
143MB 라 이력이 금방 무거워지고, 수집 스크립트로 다시 만들 수 있다.

화면만 볼 거면 그대로 `npm run dev` 하면 된다. 화면이 읽는 JSON(`src/data/real/*`)은
저장소에 들어 있다. **가공·점수 스크립트를 돌리려면** DB 가 필요한데, 며칠치를 다시
수집하는 대신 [Releases](../../releases) 의 스냅샷을 받는다:

```bash
unzip soom-data-2026-08-17.zip -d data/
npm run report:stage1     # 수집 현황 확인
```

가공 명령은 **순서가 있다.** 지키지 않으면 오류 없이 조용히 빈 결과가 나온다:

```
load:raw → dedup → build:places → build:tags
export:tagscores → export:places → export:channels
```

## 지켜야 하는 기준

단순해 보여서 건드리면 **오류 없이 조용히 깨지는** 자리들이다. 전부 실측하다 데인 것들이라,
자세한 경위는 [`CLAUDE.md`](CLAUDE.md) 에 사건별로 적어 뒀다.

| 원칙 | 그 자리에서 실제로 있었던 일 |
|---|---|
| 언어별 점수판은 따로 둔다 | 재래시장은 영어권 4.1배 / 한국어권 0.6배. 합치면 전부 평균으로 수렴한다 |
| 배수 표시 자격은 `canShowMultiplier` 한 곳에서만 판정한다 | 판정이 세 군데에 있었고 서로 달라서, 같은 장소가 화면마다 다른 말을 했다 |
| 희소성 가중치를 유지한다 | 빼면 서울·부산만 남아 공모전 주제와 정반대 결과가 나온다 |
| 화면은 외부 API 를 부르지 않는다 | 쿼터가 마르면 시연 중에 서비스가 멈춘다 |
| 못 재는 것은 숫자로 그리지 않는다 | 기관 담당자는 그 수치로 예산을 짠다 |
| 순위를 지어내지 않는다 | 그럴듯하게 만들려고 넣은 계수는 점수를 지어내는 것과 같다 |

> 커밋 메시지에 **왜 그렇게 정했는지**를 적어 뒀다. 코드보다 그쪽이 중요한 경우가 많다.
