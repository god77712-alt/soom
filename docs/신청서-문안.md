# B. data.go.kr 트래픽 증가 요청 문안

> A-1 의 각 오퍼레이션에 같은 내용으로 넣는다. 표의 숫자만 바꾼다.
> 위치: 마이페이지 → 오픈API → 활용신청 상세 → 트래픽 증가 요청

### 활용 목적

인구감소지역의 촬영지를 영상 크리에이터에게 추천하는 웹 서비스입니다.
관광지 소개글을 소재 단위(오일장·등대·폐교 등)로 분류한 뒤, 같은 소재의
영상이 실제로 어떤 성과를 냈는지와 대조해 "이 지역에서 이 소재를 찍으면
어떤 결과가 나오는가"를 데이터로 제시합니다.

분류의 근거가 소개글 본문이기 때문에, 일부 표본이 아니라 **전국 전수의
소개글이 있어야 서비스가 성립**합니다. 특정 지역만 수집하면 데이터가 있는
수도권·광역시로 추천이 쏠려, 인구감소지역 활성화라는 목적과 정반대의
결과가 나옵니다.

### 증가 요청 사유

`detailCommon2`·`detailIntro2`·`detailImage2` 는 콘텐츠 1건당 1회 호출
구조입니다. 현재 오퍼레이션당 1,000회/일 기준으로 계산하면:

```
국문 소개글      48,929회 ÷ 1,000/일 =  49일
장날·운영시간    48,929회 ÷ 1,000/일 =  49일
장소 이미지      48,929회 ÷ 1,000/일 =  49일
영문 소개글      15,108회 ÷ 1,000/일 =  15일
                                 합계  162일
```

수집만으로 162일이 소요되어, 이후 분류·점수 계산·화면 연결에 필요한 기간을
포함하면 공모전 접수 기한 내 완성이 불가능합니다.

현재까지 개발계정 한도 내에서 목록 64,037건(국문 48,929 + 영문 15,108)과
사진·수상작·걷기길 6,365건 수집을 완료했습니다. 소개글은 3,991건까지 받아
**확보율 99.6%·평균 309자**를 확인했으며, 수집 로직과 오류 처리(게이트웨이
오류 구분, 실패분 재시도, 이어받기) 검증도 마쳤습니다.
**남은 병목은 일일 한도 하나뿐입니다.**

요청 한도는 각 오퍼레이션의 전체 대상 건수에 재시도 여유를 더한 값이며,
승인 시 **1일 내 수집을 완료**하고 즉시 분석 단계로 진입할 수 있습니다.

### 시스템 및 보안

- 수집은 서버 사이드 배치 스크립트로만 수행하며, 결과를 자체 DB에 적재합니다.
- **웹 화면에서는 API 를 직접 호출하지 않습니다.** 모든 조회는 자체 DB 기준이며,
  이용자 트래픽이 곧바로 API 호출로 이어지는 구조가 아닙니다.
- 인증키는 서버 환경변수로만 관리하며 클라이언트에 노출되지 않습니다.
- 동시 요청 4건 · 요청 간 지연을 두어 서버 부하를 제한합니다.
- 성공분은 상태값으로 기록해 재실행 시 중복 호출하지 않으며, 실패분만
  재요청합니다.
- 연속 실패 50회 시 자동 중단하는 안전장치를 두어, 오류 상황에서 무한
  재시도가 발생하지 않도록 했습니다.

등대·해안·산지 등 소재는 일출·일몰 및 박명 시각이 촬영 결과를 좌우하므로,
추천 장소의 좌표가 속한 지역 기준 출몰시각을 함께 표시합니다.

시도 17개 지역 × 1년치를 1회 사전 수집해 자체 DB에 적재하며(약 6,205회),
이용자 화면에서는 API 를 직접 호출하지 않습니다.

### 기상청 종관기상관측(ASOS) / 단기예보

계절별 촬영 적합도를 제시하는 데 사용합니다. ASOS 과거 관측으로 지역·시기별
맑음 비율을 산출하고(1회 수집), 단기예보로 임박한 장날·축제일의 강수확률을
표시합니다(1일 1회 배치). 두 경우 모두 자체 DB 적재 후 조회합니다.

# D. YouTube Data API — Audit and Quota Extension Form

**양식**: YouTube API Services - Audit and Quota Extension Form
**요청 한도**: **300,000 units/day** (현재 기본 10,000)

### Description of your API Client

SOOM is a location recommendation service for video creators, built for a
public tourism data competition in Korea. It helps creators discover filming
locations in depopulating rural regions by showing how videos on comparable
subjects have actually performed.

The service does not host, download, or redistribute any YouTube content.
It reads public metadata to compute an aggregate performance score per
subject tag (e.g. traditional five-day markets, lighthouses, closed schools),
and displays the results as statistics with links back to the original
videos on YouTube.

### How the API is used

| Call | Purpose |
|---|---|
| `search.list` | Collect candidate videos per subject tag and per region name |
| `videos.list` | Statistics, duration, and description (chapter timestamps), 50 ids per call |
| `commentThreads.list` | Identify the filming location named by viewers in comments |
| `channels.list` | Subscriber count, for normalizing performance by channel size |

### Quota calculation

Target dataset: 15,000 videos each for Korean and English, published within
the last three years.

```
search.list         ~1,000 queries x 3 pages x 100 units = 300,000 units
videos.list         30,000 videos / 50 per call x 1 unit =     600 units
commentThreads.list 1 page for each of 30,000 videos     =  30,000 units
channels.list       ~4,000 channels / 50 per call        =      80 units
                                                       ──────────────────
                                             one-time      ~330,700 units
```

The ~1,000 queries come from 229 municipalities x 2 Korean phrasings, plus
roughly 150 subject tags x 2 languages, plus a small set of English generic
queries.

### Reason for extension

Under the default 10,000 units/day, `search.list` at 100 units per call
allows only 100 searches per day. Building the initial dataset would take
approximately **33 days of uninterrupted collection** with no margin for
retries or corrections, which does not fit the competition timeline.

Scores must be computed separately per language, because subject performance
differs sharply between Korean and English audiences in our sample data
(traditional markets: 4.1x for English-language videos versus 0.6x for
Korean-language ones). Merging the two would collapse every tag toward the
mean and make the recommendation meaningless, so both language sets have to
be collected in full rather than sampled.

Comments are necessary because English-language travel videos usually do not
name the location in the title (e.g. "I Visited Korea's Most Beautiful
Village"). Korean viewers identify the place in the comments, and that is
our only way to attribute such videos to a specific region.

At 300,000 units/day the initial collection completes within about two days,
after which ongoing use drops to roughly 10,000 units/day for periodic
re-scoring.

### Compliance

- No YouTube content is downloaded, stored as media, or re-hosted.
- Only public metadata is stored, and every displayed video links back to
  its YouTube watch page.
- Stored statistics are refreshed periodically rather than retained
  indefinitely as a static copy.
- Aggregate figures are presented as estimates with explicit ranges and a
  visible disclaimer, never as guaranteed outcomes.
- No user authentication and no access to private user data is involved.
- The API key is held server-side only and is never exposed to the browser;
  the web front end makes no direct calls to the YouTube API.
