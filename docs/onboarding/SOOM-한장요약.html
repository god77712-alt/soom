크리에이터는 잘 된 영상을 보고 따라 찍는다. 그래서 이미 찍힌 곳만 계속 찍히고, 안 알려진 곳은 참고할 영상이 없어 구조적으로 후보에서 빠진다.
대표 문장 — 여기서 찍으면 잘 된다 → 이 소재가 반응이 좋고, 여기서도 찍을 수 있다  (실측하고 바꿨다. 아래 가설 B)

어떻게 푸는가

장소가 아니라 소재(subject)를 성과의 단위로 삼는다. 유튜브에서 소재별 성과를 재고, 공공데이터에서 같은 소재를 찍을 수 있는 곳을 전부 펼친다.

  • 성과 = 조회수 ÷ 구독자 — 채널 크기를 지워야 작은 채널의 대박이 보인다
  • 소재 점수 × 희소성 1/log(1+영상수) = 숨 스코어
  • 화면은 “오일장 3.2× (정선·화개장터 기준)” — 출처를 밝힌 소재 성적만 말한다

왜 지금 가능한가

관광 공공데이터 6.4만 곳은 소재로 검색할 수 없다. 분류는 있어도 성과가 없다. 그 둘을 처음으로 붙였다.

  • 지역코드 확보율 45.6% → 100% — 인구감소지역별 소재 집계가 처음 가능해졌다
  • 폐교 334곳은 TourAPI 에 아예 없어서 직접 승격시켰다 (감소지역 194)
  • 화면은 외부 API 를 안 부른다. 빌드 시점 JSON — 방문자가 늘어도 쿼터 0

어떻게 설명할 것인가

  • 재료가 아니라 질문부터. “관광데이터를 썼다”가 아니라 “크리에이터가 다음 촬영지를 어떻게 정하는가”
  • 기각된 가설을 먼저 보여준다. 숨기면 “왜 빈 곳을 올리냐”에 답할 말이 없다
  • 아는 곳으로 증명한다. 정선 5일장은 추천이 아니라 증거다 — 정선이 맞아야 곡성을 믿는다. 단 같은 목록에 섞지 않는다

손대면 안 되는 것

  1. 언어별 점수판을 합치지 않는다 — 재래시장은 영어권 4.1배 / 한국어권 0.6배
  2. 배수 표시 자격은 한 함수에서만 판정한다 (canShowMultiplier)
  3. 못 재는 것을 숫자로 그리지 않는다 — 기관은 그 수치로 예산을 짠다
  4. 순위를 지어내지 않는다 — 근거 없는 계수는 점수를 지어내는 것과 같다
