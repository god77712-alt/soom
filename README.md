## 무엇을 푸는가

크리에이터는 **잘 된 영상을 보고 따라 찍는다.** 그래서 이미 찍힌 곳만 계속 찍히고,
안 알려진 곳은 참고할 영상이 없어서 **구조적으로 후보에서 빠진다.**

그래서 장소가 아니라 **소재(subject)** 를 성과의 단위로 삼는다.
유튜브에서 소재별 성과를 재고, 공공데이터에서 **같은 소재를 찍을 수 있는 곳을 전부 펼친다.**

- 성과 = **조회수 ÷ 구독자(vsr)** — 채널 크기를 지워야 작은 채널의 대박이 보인다
- 숨 스코어 = 소재 점수 × 희소성 가중치 `1 / log(1 + 영상수)`
- 화면은 **“오일장 3.2× (정선·화개장터 기준)”** 처럼 **출처를 밝힌 소재 성적**만 말한다

## 가설을 실제로 검정했다

| | 결과 |
|---|---|
| A · 소재가 성과를 가르는가 | ✅ 그렇다 (p=0.0007, 구독자 구성 보정 후) |
| B · 비어 있는 곳이 기회인가 | ❌ **뒷받침되지 않는다** (곡성 0.79배) |
| 분산 분해 | 채널이 74.2% — **소재는 부차적이다** |

가설 A 도 **BH 보정 후 유의한 쌍은 0개**다. → 점수는 **순위로만** 쓰고 근소한 차이를
의미 있는 것처럼 그리지 않는다. 가설 B 가 기각됐으므로 희소성 가중치는
**예측이 아니라 정책**이다 — 화면은 `경쟁 영상 0편` 이라는 **사실만** 말한다.

`npm run eval:hypothesis` 로 언제든 다시 잰다.

## 구조

```
수집 → 정리 → 태깅 → 점수 → 화면
```

**화면은 어떤 외부 API 도 부르지 않는다.** 빌드 시점에 구운 JSON(`src/data/real/*`)만 읽는다.
방문자가 늘어도 쿼터 소비는 0이고, 시연 중에 서비스가 멈추지 않는다.

| 문서 | 역할 |
|---|---|
| [`CLAUDE.md`](CLAUDE.md) | **작업 규칙과 실측 기록.** 손대기 전에 반드시 읽는다 |
| [`SPEC.md`](SPEC.md) | 전체 설계 (데이터 모델·계산식·화면) |
| `scripts/` | 수집·가공·검증·내보내기 |
| `src/` | Next.js 화면 |

## 돌려보기

```bash
npm install
cp .env.example .env      # 키를 채운다. 화면만 볼 거면 비워도 된다
npm run dev
```

**데이터는 저장소에 없다.** `data/*.db` 와 `.env` 는 커밋하지 않는다 —
용량이 크고 수집 스크립트로 다시 만들 수 있다. 순서가 있다:

```
load:raw → dedup → build:places → build:tags
export:tagscores → export:places → export:channels
```

**순서를 지키지 않으면 오류 없이 조용히 빈 결과가 나온다.**

## 같이 일할 때 지켜야 하는 것

“단순화하면 편해 보이지만 서비스 목적이 깨지는” 것들이다.
전체 목록과 **각각의 이유**는 [`CLAUDE.md`](CLAUDE.md) 「절대 하면 안 되는 것」에 있다.

1. **한국어·영어 점수판을 합치지 않는다** — 재래시장은 영어권 4.1배 / 한국어권 0.6배다
2. **배수를 그릴 자격은 `score.ts` `canShowMultiplier` 한 곳에서만 판정한다** — 예전에 세 군데에 있었고 서로 달랐다
3. **희소성 가중치를 빼지 않는다** — 빼면 서울·부산만 남아 공모전 주제와 정반대가 된다
4. **화면에서 YouTube API 를 직접 부르지 않는다** — 쿼터가 마르면 시연이 멈춘다
5. **못 재는 것을 숫자로 그리지 않는다** — 기관 담당자는 그 수치로 예산을 짠다
6. **순위를 지어내지 않는다** — 그럴듯하게 만들려고 만든 임계값·계수는 점수를 지어내는 것과 같다

> 커밋 메시지에 **왜 그렇게 정했는지**를 적어 두었다. 코드보다 그쪽이 중요한 경우가 많다.
