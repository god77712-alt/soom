## 개요

크리에이터가 **다음 촬영지 고를 때 보는 도구**야. 채널을 넣으면 그 채널이 뭘 잘 찍는지
판별하고, **같은 소재를 찍을 수 있는 인구감소지역**을 성과 데이터랑 같이 쭉 펼쳐준다.

한국관광공사 TourAPI **5만 곳**이랑 유튜브 **8.3만 편**을 **소재(subject)라는 축 하나로**
붙인 것, 그게 이 서비스의 실체다.

## 과제 — 일회성 관광의 한계

인구감소지역 89곳 관광 사업은 대부분 **축제·행사**다. 돈 써서 사람 한 번 모으고, 끝나면
올 이유도 같이 사라진다. **남는 게 없어.**

- 홍보물은 게시 기간 끝나면 사라진다 — **검색이 안 된다**
- 공공데이터 6.4만 곳은 **소재로 검색이 안 된다.** 분류는 있는데 성과가 없으니까
- 그래서 크리에이터 촬영지 후보에 **애초에 안 올라간다**

## 해결 — 크리에이터를 거쳐서 계속 오게 만든다

촬영은 한 번이지만 **영상은 남는다.** 검색되고, 추천되고, 몇 년 뒤에도 사람을 데려온다.
그래서 관광객 말고 **크리에이터**를 움직이는 거다.

| | |
|---|---|
| **① 후보지에 올린다** | 인구감소지역을 “처음 듣는 지명”이 아니라 **같은 소재를 찍을 수 있는 선택지**로 보여준다. 희소성 가중치 빼면 서울·부산만 남는다 |
| **② 예상 성과를 보여준다** | 그 소재가 이 채널 규모에서 어떤 성과를 냈는지 배수랑 **도달 범위**로. 단일 숫자로는 절대 안 쓴다 |
| **③ 의심을 걷어낸다** | “별로라서 아무도 안 간 거 아냐?”에 답 못 하면 안 움직인다. 상세 화면이 6단으로 이 순서를 밟는다 |

계산 뼈대는 이거 셋:

- 성과 = **조회수 ÷ 구독자(vsr)** — 채널 크기를 지워야 작은 채널의 대박이 보인다
- 숨 스코어 = 소재 점수 × 희소성 `1 / log(1 + 영상수)`
- 화면은 **“오일장 3.2× (정선·화개장터 기준)”** 처럼 **출처를 밝힌 소재 성적**만 말한다

## 기능 명세

| 화면 | 사용자가 하는 일 | 서비스가 주는 것 | 데이터 근거 |
|---|---|---|---|
| **채널 분석** `/` | 채널 URL 을 넣는다 (없으면 소재를 직접 고른다) | 롱폼·쇼츠 성과, **잘 되는 소재 태그 3~5개**. 평균이 아니라 **잘 된 영상**에서 뽑는다 | YouTube Data API · LLM 소재 분류 |
| **촬영지 추천** `/` | 추천 5곳을 훑고 카드를 펼친다 | 장소 · **소재 성적과 그 출처** · **경쟁 영상 수** · 잘 된 영상 구성 · 묶어서 찍을 곳 | 숨 스코어 |
| **소재로 찾기** `/subject` | 소재를 고르고 시도로 좁힌다 | 그 소재 찍을 수 있는 곳 **전부** · 장날 달력 · 일출입 시각. 예측이 아니라 **목록**이다 | TourAPI + 전통시장·폐교·철도역 표준데이터 |
| **장소 상세** `/place` | 가도 되는지 판단한다 | **6단 근거** — ① 소재가 먹힌다 ② 여긴 비어 있다 ③ **별로라서가 아니다** ④ 당신이면 이 정도 ⑤ 이렇게 찍는다 ⑥ 이렇게 머문다 | 유튜브 임베드 · 천문연 출몰시각 · 관광사진 |
| **기관용** `/admin` | 지역별 현황을 본다 | 시군구별 소재 보유 현황 **(모수 병기)** · 팸투어 채널 매칭. **못 재는 KPI 는 안 그린다** | 지역코드 100% 복원 집계 |

## 근거 — 깔고 있던 가정을 직접 재봤다

| | 결과 |
|---|---|
| A · 소재가 성과를 가르나 | ✅ 그렇다 (p=0.0007, 구독자 구성 보정 후) |
| B · 비어 있는 곳이 유리한가 | ❌ **아니다** (곡성 0.79배) |
| 분산 분해 | 성과의 **74.2%가 채널 본인** — 소재 몫은 25.8% |

가설 A 도 **BH 보정하면 통과하는 쌍이 0개**다. → 점수는 **순위로만** 쓰고, 근소한 차이를
의미 있는 것처럼 그리지 않는다. B 가 기각됐으니 희소성 가중치는 **예측이 아니라 정책**이다 —
화면은 `경쟁 영상 0편` 이라는 **사실만** 말하고 판단은 크리에이터한테 넘긴다.

`npm run eval:hypothesis` 로 언제든 다시 잰다.

## 구조

```
수집 → 정리 → 태깅 → 점수 → 화면
```

**화면은 외부 API 를 하나도 안 부른다.** 빌드할 때 구워둔 JSON(`src/data/real/*`)만 읽는다.
방문자가 늘어도 쿼터는 0이고, 시연 중에 멈출 일이 없다.

| 문서 | 역할 |
|---|---|
| [`CLAUDE.md`](CLAUDE.md) | **작업 규칙이랑 실측 기록.** 손대기 전에 이것부터 |
| [`SPEC.md`](SPEC.md) | 전체 설계 (데이터 모델·계산식·화면) |
| [`docs/WORKLOG.md`](docs/WORKLOG.md) | **날짜별 작업 로그.** 언제 뭘 왜 했는지 — `npm run worklog` 으로 다시 굽는다 |
| `scripts/` | 수집·가공·검증·내보내기 |
| `src/` | Next.js 화면 |

## 돌려보기

```bash
npm install
cp .env.example .env      # 키를 채운다. 화면만 볼 거면 비워도 된다
npm run dev
```

**DB 는 저장소에 없다.** `data/*.db` 랑 `.env` 는 커밋 안 한다 — 143MB 라 이력이 금방
무거워지고, 어차피 수집 스크립트로 다시 만들 수 있어서.

화면만 볼 거면 그냥 `npm run dev` 하면 된다. 화면이 읽는 JSON 은 저장소에 있으니까.
**수집·점수 스크립트를 돌리려면** 각자 자기 API 키로 모아야 한다 (`.env.example` 참고).
유튜브 원본 데이터는 약관상 재배포를 못 해서 공유하지 않는다.

가공 명령은 **순서가 있다.** 안 지키면 오류도 없이 조용히 빈 결과가 나온다:

```
load:raw → dedup → build:places → build:tags
export:tagscores → export:places → export:channels
```

## 지켜야 하는 기준

단순해 보여서 건드리면 **오류도 없이 조용히 깨지는** 자리들이다. 전부 하다가 데인 것들이고,
자세한 경위는 [`CLAUDE.md`](CLAUDE.md) 에 사건별로 적어놨다.

| 기준 | 그 자리에서 실제로 있었던 일 |
|---|---|
| 언어별 점수판은 따로 둔다 | 재래시장이 영어권 4.1배 / 한국어권 0.6배. 합치면 전부 평균으로 수렴해버린다 |
| 배수 표시 자격은 `canShowMultiplier` 한 곳에서만 본다 | 판정이 세 군데에 있었는데 서로 달라서, 같은 장소가 화면마다 다른 말을 했다 |
| 희소성 가중치는 유지한다 | 빼면 서울·부산만 남는다. 공모전 주제랑 정반대가 된다 |
| 화면에서 외부 API 를 안 부른다 | 쿼터 마르면 시연 도중에 서비스가 멈춘다 |
| 못 재는 건 숫자로 안 그린다 | 기관 담당자는 그 수치로 예산을 짠다 |
| 순위를 지어내지 않는다 | 그럴듯하게 보이려고 넣은 계수는 점수를 조작하는 거랑 같다 |

> 커밋 메시지에 **왜 그렇게 정했는지**를 적어놨다. 코드보다 그쪽이 중요한 경우가 많다.
